BTW — Side Thread
Also available from the wand menu, or with /btw <question>.

Connection

The side thread can use its own backend so a cheap model answers questions while your roleplay model keeps writing. "Main API" reuses whatever SillyTavern is connected to.
Requests go straight from the browser, so the server must allow this origin (OLLAMA_ORIGINS).
The key is stored in your SillyTavern settings, not in the secrets store.
Applied to connection-profile requests only — and in that mode it is the only way to give the side thread its own sampler settings. Point it at a preset with some temperature (around 0.8) so a deterministic roleplay preset does not flatten the personality.

Stale lore audit

The clock icon in the panel header reviews your lorebook entries, card fields and persona against what the story has become, and reports verbatim old → new spans to paste by hand. It loads the books directly, so the lore mode above does not limit it — an audit has to see the entries that are not currently triggering.
The story context is re-sent with every batch, so this is capped separately from the chat history above: "entire chat" would be paid for once per request. The running summary carries what falls outside the window — keep the Summarize extension on for a long chat. Smaller batches mean more requests but closer reading: a model given twenty entries at once answers about three of them. Coverage is checked either way — anything it fails to rule on is reported as unanswered, never as clean. The OK: line and the #### E<n> headings are how coverage is counted. Change that part of the format and the audit can no longer tell you what it missed.
